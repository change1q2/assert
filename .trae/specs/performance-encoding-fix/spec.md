# 理财模块性能优化与编码修复 PRD

## Overview
- **Summary**: 对理财模块进行四项关键改进：(1) 实现渐进式数据加载，优先渲染当前页数据，其他数据随后台补充；(2) 清理并防止资产种类脏数据（"??"乱码）；(3) 修复账户余额与资产列表余额不一致问题；(4) 全局排查并修复中文乱码显示问题。
- **Purpose**: 解决用户反馈的页面加载慢、数据显示异常（乱码、负数）等核心体验问题。
- **Target Users**: Wealth OS 理财模块的所有使用者。

## Goals
- 提升理财模块页面加载速度，减少白屏等待时间
- 彻底消除"??"乱码数据，恢复正确的中文显示
- 确保账户余额与资产列表余额保持一致
- 允许余额为负数时仍可增加资产（用户要求）

## Non-Goals
- 不改变现有数据模型和API契约
- 不重构整个前端架构
- 不修改数据库表结构

## Background & Context
- 技术栈：React + Vite + Tailwind 前端，Node.js + Express + MySQL 后端
- 当前 `loadData` 函数一次性加载全部数据（汇率、行情、基金净值），造成首屏等待时间过长
- 行情接口使用 GBK 解码（`TextDecoder("gbk")`），但部分数据源返回的中文可能解码失败
- 资产余额计算存在 `Math.max(0, ...)` 强制非负逻辑，导致显示不一致
- `finance_asset_kind_options` localStorage 存储可能因浏览器编码问题产生脏数据

## Functional Requirements
- **FR-1**: 页面首屏仅加载当前页（默认10条）的行情数据，其余数据在后台异步补齐
- **FR-2**: 资产种类下拉选项中自动过滤"??"或空字符串等无效值，并在初始化时自动清理
- **FR-3**: 当数据库中资产种类、资产名称、市场等字段为"??"时，使用API返回的正确值覆盖；如API返回也异常则保留原始值
- **FR-4**: 账户余额为正数时资产列表不应显示负数；允许余额为负数时增加资产
- **FR-5**: 全局排查所有中文文本显示"??"的情况，修复编码解码链路

## Non-Functional Requirements
- **NFR-1**: 首屏可交互时间（TTI）较当前降低 50% 以上
- **NFR-2**: 行情数据准确率不低于 99%
- **NFR-3**: 所有中文字段显示正常，无"??"乱码

## Constraints
- **Technical**: 保持现有 API 接口不变；前端 React 版本和组件结构不变
- **Dependencies**: 依赖东方财富、腾讯、新浪等第三方行情数据源

## Assumptions
- 第三方行情接口在请求超时时可正确返回错误
- 用户浏览器支持 ES2020+ (Promise.allSettled, optional chaining)
- localStorage 中存储的旧脏数据可以通过迁移脚本一次性清理

## Acceptance Criteria

### AC-1: 渐进式数据加载
- **Given**: 用户首次进入理财模块
- **When**: 页面加载完成
- **Then**: 首屏在 2 秒内显示当前页数据（含行情），其余页数据在 30 秒内陆续加载完毕
- **Verification**: `programmatic`
- **Notes**: 通过浏览器 Performance 面板测量 TTI

### AC-2: 资产种类乱码清理
- **Given**: 数据库中存在"??"或空字符串的资产种类记录
- **When**: 用户打开资产种类下拉选择框
- **Then**: 下拉列表仅显示有效中文选项，"??"项被自动过滤
- **Verification**: `human-judgment`
- **Notes**: 手动检查下拉选项是否干净

### AC-3: 中文名称自动修复
- **Given**: 资产名称、市场、资产种类等字段在数据库中为"??"
- **When**: 行情数据返回该资产的正确名称
- **Then**: "??"被自动替换为行情接口返回的正确中文名称
- **Verification**: `programmatic`
- **Notes**: 检查数据库或状态快照中的字段是否被正确更新

### AC-4: 余额一致性
- **Given**: 账户余额为正数
- **When**: 在资产列表中查看该账户关联的资产
- **Then**: 资产列表中的余额/市值计算正确，不出现负值
- **Verification**: `human-judgment`

### AC-5: 允许负数余额增加资产
- **Given**: 账户余额为负数
- **When**: 用户尝试新增资产到该账户
- **Then**: 操作成功，不因为余额为负而被阻止
- **Verification**: `programmatic`

### AC-6: 全局编码正确
- **Given**: 用户在任意页面查看数据
- **When**: 数据包含中文字段
- **Then**: 所有中文字段正确显示，无乱码
- **Verification**: `human-judgment`
