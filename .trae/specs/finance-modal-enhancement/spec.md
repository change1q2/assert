# 理财模块新增弹窗增强 - Product Requirement Document

## Overview
- **Summary**: 对理财模块新增/编辑持仓弹窗进行功能增强，包括所属账户数据源统一、资产分类与资产类型联动、现价实时获取，确保前端数据全部来自后端数据库。
- **Purpose**: 提升用户体验，统一数据来源，减少重复维护，确保资产分类与类型的智能联动，以及新增时自动获取最新行情数据。
- **Target Users**: 理财模块使用者，需要新增/编辑持仓记录的用户。

## Goals
- 所属账户下拉选项从账户管理模块统一获取，移除弹窗内的账户设置入口
- 资产分类从资产分类模块获取一级分类列表
- 资产分类二级/三级选项与资产类型智能联动
  - 股票 → 二级：A股、港股、美股、其他
  - 基金 → 二级：混合型、指数型、货币型、债券型、行业主题型
  - 基金 → 三级：场外、场内
- 新增时选择代码/名称后自动实时获取最新现价
- 前端所有数据从后端 API 获取，与数据库保持同步

## Non-Goals (Out of Scope)
- 不改变账户管理模块的现有功能
- 不改变资产分类模块的现有功能
- 不改变列表页的现有数据展示逻辑
- 不新增后端 API 接口（复用现有 fetchState、lookupFinance、fetchFinanceQuotes）

## Background & Context
- 现有代码中，所属账户下拉选项从 financeAssets 中收集唯一账户名，数据源不一致
- 资产分类二级/三级目前从 assetClasses 动态联动，但未根据资产类型做特殊处理
- 现价获取已有基础逻辑，需确保稳定性和用户体验
- 项目采用前后端分离架构，前端通过 fetchState 获取状态数据
- 资产分类系统包含权益类、商品类、债权类、现金类四大默认分类

## Functional Requirements

- **FR-1**: 所属账户从账户管理模块获取
  - 新增弹窗"所属账户"下拉选项从 `state.accounts`（账户管理模块数据）读取
  - 显示账户名称，保存时存储账户 ID 或名称
  - 移除"所属账户"旁边的设置（Settings）按钮
  - 账户管理模块的增删改需实时反映到理财模块的账户下拉中

- **FR-2**: 资产分类从资产分类模块获取
  - 资产分类一级下拉选项从 `state.assetClasses` 获取
  - 无数据时降级使用本地默认值

- **FR-3**: 资产分类二级与资产类型联动（股票/基金特殊处理）
  - 资产类型选择"股票"时，二级分类显示：A股、港股、美股、其他
  - 资产类型选择"基金"时，二级分类显示：混合型、指数型、货币型、债券型、行业主题型
  - 资产类型选择"基金"时，三级分类显示：场外、场内
  - 其他资产类型时，二级/三级仍从 assetClasses 正常联动
  - 切换资产类型时，自动重置二级/三级分类选择

- **FR-4**: 新增时现价实时获取
  - 用户在代码/名称输入框输入并选择搜索结果后，自动获取最新价格
  - 自动填充到"现价"字段
  - 现价变化时自动重新计算当前价值、持仓盈亏、盈亏率
  - 获取失败时保留用户手动输入或显示空值

- **FR-5**: 前端数据统一从后端获取
  - 所有列表/筛选/下拉数据均通过 fetchState 从后端获取
  - 确保与数据库数据同步
  - 本地 mock 数据仅作为降级 fallback

## Non-Functional Requirements

- **NFR-1**: 性能 - 现价获取响应时间 < 2秒
- **NFR-2**: 兼容性 - 保持与现有数据结构的向后兼容
- **NFR-3**: 可靠性 - 网络请求失败时有降级处理，不阻塞用户操作
- **NFR-4**: 构建验证 - 修改后 `npm run build` 必须通过

## Constraints
- **Technical**: React 前端 + Node.js 后端 + MySQL 数据库
- **Business**: 需保持现有数据结构兼容性，不破坏已有数据
- **Dependencies**: 依赖现有 API 接口（fetchState、lookupFinance、fetchFinanceQuotes）

## Assumptions
- state.accounts 包含账户管理模块的所有账户数据，每条数据有 id 和 name 字段
- state.assetClasses 包含资产分类模块的完整分类树（一级→二级→三级）
- fetchFinanceQuotes 接口支持根据代码获取实时行情
- lookupFinance 接口支持代码/名称模糊搜索并返回基础行情数据

## Acceptance Criteria

### AC-1: 所属账户从账户管理获取
- **Given**: 用户已登录且账户管理模块有账户数据
- **When**: 用户打开新增持仓弹窗
- **Then**: "所属账户"下拉框显示账户管理模块中所有账户名称
- **And**: 下拉框旁边没有设置/齿轮按钮
- **Verification**: `human-judgment`

### AC-2: 账户数据与账户管理同步
- **Given**: 用户在账户管理模块中新增/编辑/删除了账户
- **When**: 用户刷新页面或重新打开理财模块新增弹窗
- **Then**: 所属账户下拉选项与账户管理模块保持一致
- **Verification**: `human-judgment`

### AC-3: 资产类型为股票时二级分类联动
- **Given**: 用户打开新增持仓弹窗
- **When**: 用户选择资产类型为"股票"
- **Then**: 资产分类二级下拉选项为：A股、港股、美股、其他
- **And**: 资产分类三级下拉不显示或为空
- **Verification**: `human-judgment`

### AC-4: 资产类型为基金时二级/三级分类联动
- **Given**: 用户打开新增持仓弹窗
- **When**: 用户选择资产类型为"基金"
- **Then**: 资产分类二级下拉选项为：混合型、指数型、货币型、债券型、行业主题型
- **And**: 资产分类三级下拉选项为：场外、场内
- **Verification**: `human-judgment`

### AC-5: 其他资产类型时正常联动
- **Given**: 用户打开新增持仓弹窗
- **When**: 用户选择资产类型为"债券"或其他非股票/基金类型
- **Then**: 资产分类二级/三级从 assetClasses 正常联动
- **Verification**: `human-judgment`

### AC-6: 切换资产类型重置分类
- **Given**: 用户已选择某资产类型及对应的二级/三级分类
- **When**: 用户切换到另一种资产类型
- **Then**: 已选择的二级/三级分类被清空重置
- **Verification**: `human-judgment`

### AC-7: 选择搜索结果后自动填充现价
- **Given**: 用户打开新增持仓弹窗，网络连接正常
- **When**: 用户在代码/名称输入框输入并从搜索结果中选择一项
- **Then**: 系统自动获取该资产的最新价格并填充到"现价"字段
- **And**: 自动重新计算当前价值、持仓盈亏、盈亏率（如果数量和成本已填写）
- **Verification**: `human-judgment`

### AC-8: 现价获取失败降级处理
- **Given**: 用户打开新增持仓弹窗，网络异常或接口失败
- **When**: 用户从搜索结果中选择一项但现价获取失败
- **Then**: 现价字段保留为空或允许用户手动输入
- **And**: 不阻塞用户继续填写其他字段
- **Verification**: `human-judgment`

### AC-9: 数据从后端API获取
- **Given**: 后端服务正常运行且数据库有数据
- **When**: 用户打开理财模块页面
- **Then**: 列表数据、账户下拉、资产分类下拉均来自后端 API（fetchState）
- **And**: 与数据库数据保持一致
- **Verification**: `programmatic`
- **Notes**: 通过浏览器开发者工具 Network 面板验证请求来源

### AC-10: 构建成功
- **Given**: 代码修改完成
- **When**: 运行 `npm run build`
- **Then**: 构建成功，无报错
- **Verification**: `programmatic`
