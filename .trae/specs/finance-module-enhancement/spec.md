# 理财模块功能增强 - Product Requirement Document

## Overview
- **Summary**: 对现有理财模块进行全面增强，包括列表筛选、字段自定义、行操作、新增弹窗优化、资产分类联动、分页逻辑等功能。
- **Purpose**: 提升理财模块的可用性和数据完整性，让用户能够更灵活地管理和查看持仓数据，同时与资产分类模块打通。
- **Target Users**: 使用理财模块管理投资持仓的个人用户。

## Goals
- 持仓列表支持多维度筛选（默认筛选 + 高级筛选）
- 列表字段支持自定义显示和排序
- 每行支持编辑和删除操作
- 新增弹窗支持代码/名称搜索匹配、自动获取现价、自动计算盈亏
- 资产分类从资产分类模块获取，保持数据一致性
- 列表展示新增弹窗的所有字段
- 列表数据支持分页

## Non-Goals (Out of Scope)
- 不做后端数据结构大改（数据仍存储在 state.accounts 中）
- 不做批量导入导出功能
- 不做复杂的图表分析（已有账户本和分类统计）
- 不做移动端专属布局优化
- 不做实时行情推送（仍为手动刷新）

## Background & Context
当前理财模块（Finance.jsx）使用 CategoryTable 组件按资产分类展示持仓表格，但存在以下问题：
1. 筛选功能薄弱，只有文本搜索
2. 表格列固定不可配置
3. 没有行级操作（编辑/删除）
4. 新增弹窗字段多但部分是冗余的（如买入均价、当日盈亏等），且没有代码联想功能
5. 资产分类使用硬编码常量，与 AssetClasses 模块不同步
6. 分页只在分类内部有，没有全局列表视图

## Functional Requirements

- **FR-1**: 持仓列表支持筛选功能，默认显示代码/名称、所属账户、市场、货币四个筛选器，其他筛选项放入"高级筛选"
- **FR-2**: 列表支持字段设置功能，可自定义显示哪些列，并可调整列的显示顺序
- **FR-3**: 列表每行最后增加"操作"列，包含编辑和删除按钮
- **FR-4**: 新增弹窗中输入代码或资产名称时，显示匹配下拉选项（从东方财富等接口获取），选择后自动获取现价
- **FR-5**: 新增弹窗中持仓成本和份额/数量为必填项；删除买入均价字段；持仓盈亏和盈亏率自动计算且支持手动编辑
- **FR-6**: 新增弹窗中删除当日参考盈亏和当日收益率字段，改为在列表中根据实时行情自动计算
- **FR-7**: 新增弹窗中当前价值自动计算（数量 × 现价）
- **FR-8**: 行情数据支持从东方财富、腾讯财经、同花顺等公共平台获取（已有 finance-service.js 基础能力）
- **FR-9**: 选择国内市场时货币单位默认 CNY
- **FR-10**: 新增弹窗的资产分类下拉选项从资产分类模块（state.assetClasses）获取，而非硬编码
- **FR-11**: 持仓明细列表的"其他"分类也使用标准列表数据展示（与其他分类一致）
- **FR-12**: 列表展示新增弹窗中的所有字段
- **FR-13**: 列表数据支持分页（全局分页，而非每个分类内部分页）

## Non-Functional Requirements

- **NFR-1**: 筛选和分页操作响应时间 < 200ms（纯前端计算）
- **NFR-2**: 代码搜索联想请求超时 < 8s（已有超时控制）
- **NFR-3**: 字段设置状态持久化到 localStorage
- **NFR-4**: 支持暗色模式
- **NFR-5**: 代码风格与现有页面保持一致

## Constraints
- **Technical**: React + Vite + Tailwind CSS；后端使用 Node.js + SQLite（整体 state 存储）
- **Business**: 行情数据来自公共免费接口，可能有延迟或失败，需有降级处理
- **Dependencies**: 依赖 finance-service.js 的 lookupSecurities 和 getQuotes 接口；依赖 state.assetClasses 数据

## Assumptions
- 用户理解行情数据有延迟，不作为交易依据
- 资产分类模块（AssetClasses）的一级分类名称与理财模块的 categoryL1 对应
- 分页每页默认显示 10 条，用户可调整

## Acceptance Criteria

### AC-1: 列表筛选功能
- **Given**: 用户在理财模块持仓明细页面
- **When**: 页面加载完成
- **Then**: 列表顶部显示默认筛选器：代码/名称搜索框、所属账户下拉、市场下拉、货币下拉
- **And**: 有一个"高级筛选"按钮/区域，点击展开显示更多筛选（资产类型、资产分类、持仓分组、持位分类、标签等）
- **Verification**: `human-judgment`

### AC-2: 字段设置功能
- **Given**: 用户在持仓明细页面
- **When**: 用户点击"列设置"按钮
- **Then**: 弹出设置面板，显示所有可用字段的复选框，可勾选/取消勾选
- **And**: 支持拖拽或上下按钮调整列的显示顺序
- **And**: 设置自动保存，刷新页面后保持
- **Verification**: `human-judgment`

### AC-3: 行操作列
- **Given**: 持仓列表有数据
- **When**: 查看列表最后一列
- **Then**: 每行都有"编辑"和"删除"操作按钮
- **And**: 点击编辑打开编辑弹窗（与新增弹窗共用，数据预填）
- **And**: 点击删除弹出确认对话框，确认后删除该条记录
- **Verification**: `human-judgment`

### AC-4: 代码/名称搜索联想
- **Given**: 用户在新增弹窗中输入代码或资产名称
- **When**: 输入内容后（防抖 300ms）
- **Then**: 显示匹配的下拉选项列表（最多 10 条），包含代码和名称
- **And**: 选择某一项后，自动填充代码、名称，并自动获取现价
- **Verification**: `human-judgment`

### AC-5: 新增弹窗字段调整
- **Given**: 用户打开新增弹窗
- **When**: 查看表单字段
- **Then**: 持仓成本和份额/数量标有红色星号（必填）
- **And**: 没有"买入均价"字段
- **And**: 持仓盈亏和盈亏率有值（自动计算），且可手动编辑
- **And**: 没有"当日参考盈亏"和"当日收益率"字段
- **And**: 当前价值自动计算且可编辑
- **Verification**: `human-judgment`

### AC-6: 国内市场默认 CNY
- **Given**: 用户打开新增弹窗
- **When**: 市场选择"国内市场"
- **Then**: 货币单位自动填充为 "CNY"
- **Verification**: `programmatic`

### AC-7: 资产分类联动
- **Given**: 用户打开新增弹窗，且系统中有资产分类数据
- **When**: 点击"资产分类"下拉框
- **Then**: 下拉选项来自 state.assetClasses 的一级分类名称，而非硬编码常量
- **Verification**: `human-judgment`

### AC-8: 列表字段完整性
- **Given**: 用户查看持仓列表
- **When**: 字段设置中勾选了所有字段
- **Then**: 列表显示新增弹窗中的所有字段
- **Verification**: `human-judgment`

### AC-9: 列表分页
- **Given**: 持仓数据超过一页（默认 10 条/页）
- **When**: 查看列表底部
- **Then**: 显示分页控件，可切换页码，显示"第 X 页 / 共 Y 页"
- **Verification**: `human-judgment`

### AC-10: 当日盈亏自动计算
- **Given**: 列表中有持仓数据且有代码
- **When**: 页面加载或用户点击刷新
- **Then**: 列表中"当日盈亏"和"日收益%"列根据实时行情自动计算显示
- **Verification**: `human-judgment`

## Open Questions
- [ ] 每页默认显示多少条数据？（假设 10 条）
- [ ] 高级筛选中具体包含哪些字段？（假设：资产类型、资产分类一级、资产分类二级、持仓分组、持位分类、标签）
- [ ] 编辑弹窗是否与新增弹窗完全复用？（假设是，通过 editMode 区分）
- [ ] 删除操作是否需要二次确认？（假设需要）
