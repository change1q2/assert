# 理财模块 - 明细弹窗账户余额与现金类资产自动创建 PRD

## Overview
- **Summary**: 在理财模块持仓明细弹窗中增加关联账户余额显示卡片；实现交易记录（买入/卖出）与关联账户余额的联动增减；当新建持仓资产时，若关联账户下没有资产一级分类为"现金类"的持仓，则自动创建一条现金类持仓资产。
- **Purpose**: 用户需要在明细弹窗中直观看到关联账户的实时余额；交易发生后关联账户余额应实时反映资金变动；现金类资产作为账户资金的载体，缺失时需自动补全。
- **Target Users**: 个人资产管理系统的理财模块用户。

## Goals
- 明细弹窗顶部增加关联账户余额卡片（数据来源于账户管理中的账户列表）
- 交易记录保存时，关联账户余额按规则联动增减
- 新建资产时，自动检测并创建关联账户的现金类持仓资产
- 现金类资产的字段按规范自动填充

## Non-Goals (Out of Scope)
- 不会修改账户管理模块的核心逻辑
- 不会修改归档持仓的显示逻辑
- 不会实现跨币种的自动汇率转换
- 不会修改其他模块（Overview、Analysis等）

## Background & Context
- **现有架构**: 前端 React (Finance.jsx) + 后端 Node.js + MySQL
- **数据存储**: 持仓资产以 `financeAssets` 数组存储，交易记录嵌入在每个资产的 `transactions` 字段中
- **账户体系**: 账户存储在 `accounts` 中，每个账户有 id、name、balance、currency 等字段
- **已有功能**: 现金账户联动（买入扣减、卖出增加）、清仓归档、所属账户余额联动已落地

## Functional Requirements

### FR-1: 明细弹窗账户余额卡片
- 在持仓明细弹窗的顶部信息区域（浮动盈亏卡片下方）增加一个账户余额卡片
- 卡片显示内容：
  - 关联账户名称（取自 `latestData.account` 或 `latestData.accountId`）
  - 当前余额（从 `stateData.accounts` 中按账户 id/name 匹配获取 `balance`）
  - 货币单位
- 样式与现有浮动盈亏卡片保持一致
- 当余额 >= 0 时显示为正常色，余额 < 0 时显示红色

### FR-2: 交易记录与关联账户余额联动
- 用户新增或编辑交易记录时，保存成功后触发关联账户余额更新：
  - **买入/建仓**：关联账户余额减少量 = 交易金额 + 交易费用
  - **卖出/清仓**：关联账户余额增加量 = 交易金额 - 交易费用
  - **分红**：不影响关联账户余额
- 更新逻辑复用现有的 `updateAccountBalance` 函数（模块级别）
- 货币单位不一致时不更新（已有逻辑）
- 余额更新与交易记录保存、持仓数量更新在同一批次状态中完成

### FR-3: 自动创建现金类持仓资产
- 当用户新建持仓资产（`handleSaveAccount`）时，在保存前检查：
  - 关联账户（`newAccount.account` 或 `newAccount.accountId`）下是否已存在资产一级分类（`categoryL1`）为"现金类"的持仓资产
  - 如果不存在，则自动创建一条现金类持仓资产
- 现金类资产的字段规范：
  - **资产名称**：`{账户名称}现金管理`（如"招商证券现金管理"）
  - **资产代码**：`{账户名称}01`，若已存在则顺延为 `02`、`03` 等
  - **市场**：与新建资产选择的市场一致
  - **货币单位**：与新建资产的货币单位一致
  - **资产种类**：现金
  - **资产一级分类**：现金类
  - **资产二级分类**：
    - 国内市场 → A股
    - 港股市场 → 港股
    - 美股市场 → 美股
  - **资产三级分类**：场内
  - **持仓分组**：现金仓位
  - **持仓分类**：现金管理
  - **持仓成本**：0
  - **份额/数量**：0
  - **持仓天数**：0
  - **现价**：0
  - **当前市值**：0
  - **持仓盈亏**：0
  - **持仓盈亏率**：0
  - **所属账户**：与新建资产的关联账户一致
  - **标签**：空

### FR-4: 现金类资产余额联动
- 当关联账户已存在现金类持仓资产时：
  - 买入/建仓交易：现金类持仓资产的"当前市值"和"份额/数量"不变化，但关联账户的 `balance` 字段扣减（金额+费用）
  - 卖出/清仓交易：关联账户的 `balance` 字段增加（金额-费用）
- 现金类资产本身不参与交易记录的创建（不生成建仓/买入/卖出记录）
- 现金类资产仅作为账户资金的可视化载体，其市值始终为 0

### FR-5: 明细弹窗余额实时刷新
- 当用户在明细弹窗中添加/编辑/删除交易记录后：
  - 关联账户余额卡片应实时更新（从最新的 `stateData.accounts` 中读取）
  - 无需手动刷新页面

## Non-Functional Requirements

### NFR-1: 数据一致性
- 账户余额更新、持仓保存、交易记录保存必须在同一 `saveState` 调用中完成
- 任何一步失败则全部回滚（利用现有 saveState 机制）

### NFR-2: 性能
- 明细弹窗加载时间不超过 1 秒
- 交易保存操作响应时间不超过 1 秒

### NFR-3: 向后兼容
- 老数据（无现金类资产的关联账户）不受影响
- 已存在的现金类资产不会被重复创建

## Constraints
- **技术**: React + JavaScript（前端）、Node.js + Express（后端）
- **框架**: 前端使用 Ant Design + Tailwind CSS
- **数据**: 现金类资产以普通 `financeAssets` 条目存储，通过 `categoryL1 === '现金类'` 识别

## Assumptions
- 用户已在账户管理中配置了至少一个账户
- 每个关联账户最多只需要一个现金类持仓资产（作为资金可视化载体）
- 现金类资产不参与盈亏计算
- 关联账户的 `balance` 字段是资金变动的唯一真实来源

## Acceptance Criteria

### AC-1: 明细弹窗显示账户余额卡片
- **Given**: 用户打开某持仓的明细弹窗
- **When**: 弹窗加载完成
- **Then**: 顶部显示关联账户的当前余额卡片，包含账户名称和余额数值
- **Verification**: `human-judgment`

### AC-2: 买入交易扣减关联账户余额
- **Given**: 用户在明细弹窗中添加一条买入交易
- **When**: 交易保存成功
- **Then**: 关联账户余额减少（金额 + 费用）
- **Verification**: `programmatic`

### AC-3: 卖出交易增加关联账户余额
- **Given**: 用户在明细弹窗中添加一条卖出交易
- **When**: 交易保存成功
- **Then**: 关联账户余额增加（金额 - 费用）
- **Verification**: `programmatic`

### AC-4: 新建资产自动创建现金类资产
- **Given**: 用户新建持仓资产，关联账户下无现金类资产
- **When**: 资产保存成功
- **Then**: 系统自动创建一条现金类持仓资产，字段符合规范
- **Verification**: `programmatic`

### AC-5: 不重复创建现金类资产
- **Given**: 关联账户下已存在现金类资产
- **When**: 用户再次新建持仓资产
- **Then**: 不重复创建现金类资产
- **Verification**: `programmatic`

### AC-6: 余额卡片实时更新
- **Given**: 用户在明细弹窗中添加交易记录
- **When**: 交易保存后
- **Then**: 账户余额卡片实时显示最新余额
- **Verification**: `human-judgment`

## Open Questions
- [ ] 现金类资产是否需要在持仓列表中显示？→ 当前假设：需要显示，但可通过筛选隐藏
- [ ] 现金类资产是否支持手动编辑？→ 当前假设：支持，但不建议用户手动修改
- [ ] 关联账户余额为负数时如何处理？→ 当前假设：允许负数，用红色标识
