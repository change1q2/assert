# 收支分析 UI/UX 优化 Spec

## Why
当前收支分析页面在日历展示、筛选项布局、汇率管理、记录列表信息密度等方面存在体验问题，用户需要更直观的日历收支展示、更合理的筛选项布局、实时汇率支持、以及更丰富的记录列表字段和可定制列功能。

## What Changes
- **日历优化**：放大日历间距，将收支金额直接放在日期数字下方对齐排列，解决小字体兼容问题
- **筛选项重构**：账本/标签/币种筛选统一放到新增/刷新按钮同一行的白色筛选项区域，移除独立的设置按钮，将设置入口移入新增弹窗
- **汇率整合**：合并汇率和币种为单一入口，汇率对接实时网络汇率 API，币种筛选器放在刷新数据前面
- **新增弹窗增强**：新增记录时支持选择币种，设置入口移入弹窗
- **占比图表图标**：收入占比和支出占比模块显示分类图标
- **记录列表增强**：
  - 显示一级分类和二级分类两列
  - 金额列显示对应币种标签
  - 新增「折合人民币」列
  - 标签和备注在列表中显示
  - 列表下方增加字段筛选行
  - 右侧增加「高级列表设置」，支持下拉选择显示字段 + 列宽拖拽调整
  - 新增分页逻辑，每页默认 20 条，支持页码切换和每页条数调整

## Impact
- Affected specs: records-finance-enhancement-20260628（基于该 spec 已完成的基础功能进行 UI 优化）
- Affected code: assert_WEB/src/pages/Records.jsx（主要修改文件）、assert_WEB/src/utils/currency.js、assert_WEB/src/api/index.js

## ADDED Requirements

### Requirement: 日历收支展示优化
The system SHALL 在日常 Tab 的日历中，将每日的收入和支出金额直接显示在日期数字下方，居中对齐排列，并放大日历单元格间距以确保文字不重叠。

#### Scenario: 日历单元格显示
- **WHEN** 用户打开日常 Tab 查看日历
- **THEN** 每个日期单元格内，日期数字居上，收入金额（绿色 + 前缀）和支出金额（红色 - 前缀）在下方分两行对齐显示
- **AND** 日历单元格高度和间距足够，小字体下不会重叠或截断

### Requirement: 筛选项布局重构
The system SHALL 将账本、标签、币种筛选器统一放置在同一行（与新增/刷新按钮同行或紧邻的上一行），以白色背景卡片形式展示，移除独立的「设置」按钮，将相关设置入口移入新增收支弹窗内。

#### Scenario: 筛选项统一展示
- **WHEN** 用户打开收支分析页面
- **THEN** 全部账本、全部标签、币种筛选器以白色卡片形式排列在同一行
- **AND** 币种筛选器放在刷新数据按钮前面
- **AND** 不再显示独立的设置/管理按钮

#### Scenario: 设置入口移入弹窗
- **WHEN** 用户打开新增收支弹窗
- **THEN** 弹窗内提供账本管理、标签管理、分类管理、汇率设置等入口

### Requirement: 实时汇率对接
The system SHALL 对接实时网络汇率 API（如 exchangerate-api.com 或类似免费 API），在用户打开页面时自动获取最新汇率，并支持手动刷新汇率。

#### Scenario: 自动获取实时汇率
- **WHEN** 用户打开收支分析页面或点击汇率刷新
- **THEN** 系统从网络 API 获取最新汇率并更新本地汇率数据
- **AND** 汇率数据显示最后更新时间

### Requirement: 币种切换全局生效
The system SHALL 在币种筛选器切换币种后，整页所有金额显示都切换为对应币种的额度（基于当前汇率换算）。

#### Scenario: 切换币种显示
- **WHEN** 用户在币种筛选器中选择 USD
- **THEN** 页面中所有金额（总收入、总支出、净收入、记录列表金额、图表数据等）都按当前汇率换算为 USD 显示
- **AND** 金额旁显示对应币种符号

### Requirement: 新增记录支持币种选择
The system SHALL 在新增收支弹窗中增加币种选择字段，用户可以为每条记录指定币种。

#### Scenario: 新增记录选择币种
- **WHEN** 用户在新增弹窗中填写记录
- **THEN** 弹窗中有币种下拉选择器，默认使用当前基准币种
- **AND** 保存后记录携带币种信息

### Requirement: 占比图表显示分类图标
The system SHALL 在收入占比和支出占比模块中，每个分类条目旁显示对应分类的图标。

#### Scenario: 占比列表显示图标
- **WHEN** 用户查看收入占比或支出占比
- **THEN** 每个分类行左侧显示分类图标（如 lucide-react 图标）
- **AND** 图标与分类名称、占比百分比一同展示

### Requirement: 记录列表字段增强
The system SHALL 在收支记录列表中增加以下字段显示：一级分类、二级分类、币种标签、折合人民币金额、标签、备注。

#### Scenario: 记录列表显示完整字段
- **WHEN** 用户查看收支记录列表
- **THEN** 列表显示：日期、账本、类型、一级分类、二级分类、金额（带币种标签）、折合人民币、标签、备注
- **AND** 金额列用对应颜色区分收入（绿色）和支出（红色）

### Requirement: 列表字段筛选行
The system SHALL 在收支记录列表表头下方增加一行筛选控件，每个字段对应一个筛选输入/下拉，支持按字段值过滤记录。

#### Scenario: 按字段筛选记录
- **WHEN** 用户在筛选行中输入或选择条件
- **THEN** 记录列表实时按条件过滤显示
- **AND** 支持文本模糊匹配、下拉精确匹配、日期范围等筛选方式

### Requirement: 高级列表列设置
The system SHALL 在记录列表右上角提供「高级列表设置」按钮，点击后弹出设置面板，支持：
1. 下拉复选框选择要显示的列
2. 拖拽调整列的显示顺序
3. 拖拽调整列宽

#### Scenario: 自定义显示列
- **WHEN** 用户点击「高级列表设置」
- **THEN** 弹出设置面板，列出所有可选字段的复选框
- **AND** 用户勾选/取消勾选控制列的显示/隐藏
- **AND** 用户拖拽调整列的顺序和宽度
- **AND** 设置自动保存到本地状态，刷新页面后保持

### Requirement: 记录列表分页
The system SHALL 在收支记录列表中实现客户端分页，每页默认显示 20 条记录，支持页码切换和每页条数调整（10/20/50/100 条）。

#### Scenario: 分页显示记录
- **WHEN** 用户查看收支记录列表
- **THEN** 列表按页显示，每页默认 20 条
- **AND** 列表底部有分页控件：上一页/下一页按钮、页码输入/选择、总页数显示
- **AND** 支持选择每页显示 10/20/50/100 条
- **AND** 筛选条件变化后分页自动回到第 1 页

## MODIFIED Requirements

### Requirement: 现有筛选项布局
**原有**: 账本、标签、币种筛选分散在页面不同位置，有独立设置按钮
**修改为**: 统一筛选项行，移除独立设置按钮

### Requirement: 汇率维护方式
**原有**: 用户手动在汇率设置弹窗中输入汇率
**修改为**: 自动从网络 API 获取实时汇率，用户可手动覆盖

## REMOVED Requirements
无移除需求
