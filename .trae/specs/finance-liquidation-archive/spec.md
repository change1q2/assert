# 理财模块 - 清仓归档与现金流管理 PRD

## Overview
- **Summary**: 为理财模块实现完整的清仓归档和现金流管理系统。修复"所属账户"下拉框无法获取账户数据的问题，修复持仓列表编辑/明细/删除操作无效的问题，增加清仓交易类型和归档列表，实现类似股票软件的现金账户联动逻辑（买入扣减现金、卖出/清仓增加现金）。
- **Purpose**: 当前理财模块缺少完整的交易闭环——卖出后资金不回流到账户、清仓后数据无归档、交易未与账户现金联动。用户需要一个完整的"买入→持有→卖出/清仓→资金回流"闭环。
- **Target Users**: 个人资产管理系统的理财模块用户，需要完整管理持仓生命周期的投资者。

## Goals
- 修复"所属账户"下拉框无数据的问题
- 修复持仓列表操作列（编辑/明细/删除）点击无效的问题
- 实现清仓交易标签和自动清仓逻辑
- 建立归档列表展示已清仓的历史持仓
- 实现买入扣减现金、卖出/清仓增加现金的账户联动
- 自动创建现金账户（当账户不存在现金账户时）
- 所有交易记录关联对应现金账户

## Non-Goals (Out of Scope)
- 不会修改记账模块（Records）的核心逻辑
- 不会修改账户模块（Accounts）的基本功能
- 不会实现真实的券商交易接口
- 不会修改其他模块（Overview、Analysis等）的展示逻辑
- 不会实现部分清仓的复杂逻辑（本期仅支持全部清仓）

## Background & Context
- **现有架构**: 前端 React (Finance.jsx) + 后端 Node.js + MySQL
- **数据存储**: 持仓资产以 `financeAssets` 数组存储，交易记录嵌入在每个资产的 `transactions` 字段中
- **交易类型**: 当前支持 4 种类型——建仓、买入、卖出、分红
- **账户体系**: 账户存储在 `accounts` 表中，每个账户有 id、name、balance、currency 等字段
- **已知 Bug**: 所属账户下拉框使用 `stateData.accounts` 但可能为空；持仓列表操作列按钮点击无效

## Functional Requirements

### FR-1: 所属账户下拉框修复
- 新增持仓表单中"所属账户"下拉框必须能正确显示账户管理中的所有账户
- 编辑持仓时"所属账户"必须显示当前选中的账户
- 下拉框数据来源于 `stateData.accounts`，需确保数据加载时序正确

### FR-2: 持仓操作按钮修复
- 持仓列表每行的"编辑"按钮必须能打开编辑弹窗
- 持仓列表每行的"明细"按钮必须能打开明细弹窗
- 持仓列表每行的"删除"按钮必须能执行删除操作并带确认
- 点击表格行任意空白区域也能打开明细弹窗（已部分实现）

### FR-3: 清仓交易类型
- 在交易记录的类型选项中增加"清仓"类型
- 清仓类型有独立的视觉标签（如灰色或橙色标签）
- 当用户添加"卖出"类型交易记录且卖出数量 >= 当前剩余持仓数量时，系统自动将类型标记为"清仓"
- **手动选择"清仓"类型时，自动填充剩余全部持仓数量（availableShares/shares）和当前价格（currentPrice）**
- **清仓后自动归档时，金额字段由系统自动计算（价格 × 数量），无需用户手动输入**

### FR-4: 归档列表
- 在理财模块增加"归档持仓"列表或标签页
- 已清仓的持仓自动从活跃持仓列表移动到归档列表
- 归档列表展示：资产名称、代码、清仓日期、最终盈亏、收益率
- **最终盈亏计算方式：卖出总金额 - 买入总金额 - 总费用（从交易明细统计得出）**
- **最终收益率计算方式：最终盈亏 / 买入总金额 × 100%**
- 归档持仓可查看明细（含完整交易历史），但不可编辑
- 支持从归档列表彻底删除记录

### FR-5: 现金账户联动 - 买入
- 用户新增"建仓"或"买入"交易记录时：
  - 找到该持仓资产关联的"所属账户"
  - 查找该账户下的现金账户（type 为 cash/wallet/bank 的账户）
  - 如果没有现金账户，自动创建一个默认现金账户
  - 从现金账户余额中扣减买入金额（含手续费）
  - 交易记录关联对应的现金账户 ID

### FR-6: 现金账户联动 - 卖出
- 用户新增"卖出"或"清仓"交易记录时：
  - 找到该持仓资产关联的"所属账户"
  - 查找该账户下的现金账户
  - 如果没有现金账户，自动创建一个
  - 向现金账户余额增加卖出金额（扣除手续费）
  - 交易记录关联对应的现金账户 ID

### FR-7: 自动创建现金账户
- 当用户首次对某账户的持仓进行交易且该账户无现金账户时，系统自动创建
- 自动创建的现金账户名称为 "{账户名称} 现金账户"
- 初始余额根据交易类型和金额计算（买入时初始余额 = 买入金额，卖出时初始余额 = 卖出金额）
- 现金账户的货币单位与持仓货币单位一致

### FR-8: 清仓自动归档
- 当持仓的可用数量（availableShares）降为 0 时，系统自动：
  - 将该持仓的所有交易记录标记为已完成
  - 在持仓数据上添加 `status: 'archived'` 标记
  - 从活跃持仓列表移除
  - 添加到归档列表
  - 计算最终盈亏并记录归档时间
  - **归档的最终盈亏必须从交易明细统计得出，而非使用 asset.holdingPnl**

### FR-10: 列表持仓数量以交易明细为准
- **活跃持仓列表中的持仓数量、成本价等核心字段，必须从交易明细动态计算，而非使用存储的静态值**
- 计算规则：
  - `当前持仓数量` = SUM(买入/建仓数量) - SUM(卖出/清仓数量)
  - `当前成本价` = SUM(买入/建仓金额) / SUM(买入/建仓数量)
  - `当前市值` = 当前持仓数量 × 当前价格
  - `浮动盈亏` = 当前市值 - 买入总成本
- 这确保了交易明细与列表数据的一致性

### FR-11: 交易记录表单UI优化
- **费用字段从表单底部移至数量字段旁边**
- **金额字段（价格×数量）在价格、数量、费用都填写后才自动计算并显示**
- 金额字段为只读（自动计算），但用户仍可手动覆盖

### FR-9: 交易记录关联现金账户
- 每笔交易记录增加 `cashAccountId` 字段
- 每笔交易记录增加 `cashAccountName` 字段（冗余存储便于展示）
- 交易保存时自动填充关联的现金账户信息
- 明细弹窗中交易记录显示关联的现金账户名称

## Non-Functional Requirements

### NFR-1: 数据一致性
- 交易处理必须是原子操作：更新持仓数量、更新现金账户余额、保存交易记录必须在同一事务中完成
- 任何一步失败则全部回滚

### NFR-2: 性能
- 持仓列表加载时间不超过 2 秒
- 交易保存操作响应时间不超过 1 秒
- 归档列表支持分页，每页至少 20 条

### NFR-3: 向后兼容
- 老数据（无 cashAccountId 的交易记录）必须正常显示
- 已有的持仓数据必须能平滑迁移
- 归档数据的存储结构必须支持未来扩展

### NFR-4: 多货币支持
- 现金账户联动必须考虑货币单位
- 不同货币的持仓交易只影响同币种的现金账户
- 货币转换不在本期处理

## Constraints
- **技术**: React + JavaScript（前端）、Node.js + Express（后端）、MySQL 数据库
- **数据库**: 需要新增 `finance_asset_archives` 表，新增 `cash_account_id` 字段到交易记录表
- **API**: 需扩展现有 `/api/state` 接口支持归档数据的读写
- **框架**: 前端使用 Ant Design + Tailwind CSS

## Assumptions
- 用户已在账户管理中配置了至少一个账户（如果没有，系统将引导用户创建）
- 每个"所属账户"可以关联一个现金账户（自动创建）
- 清仓操作仅支持"全部清仓"，不支持部分清仓
- 卖出/清仓产生的资金直接进入现金账户，不考虑T+1到账等实际交易规则
- 手续费在现金账户联动中扣除（买入时加手续费，卖出时扣手续费）

## Acceptance Criteria

### AC-1: 所属账户下拉框显示账户
- **Given**: 用户已登录且账户管理中存在至少一个账户
- **When**: 用户打开新增持仓表单或编辑持仓表单
- **Then**: "所属账户"下拉框中显示所有账户的名称
- **Verification**: `programmatic`

### AC-2: 持仓操作按钮功能正常
- **Given**: 持仓列表中存在至少一条持仓记录
- **When**: 用户点击某行的"编辑"、"明细"或"删除"按钮
- **Then**: 对应功能正确执行（编辑弹窗、明细弹窗、删除确认）
- **Verification**: `programmatic`

### AC-3: 清仓交易类型
- **Given**: 用户在明细弹窗的交易记录中添加新记录
- **When**: 用户选择交易类型为"清仓"
- **Then**: 显示清仓标签，自动填充剩余持仓数量
- **Verification**: `human-judgment`

### AC-4: 自动清仓归档
- **Given**: 用户添加的卖出交易数量 >= 当前持仓数量
- **When**: 用户保存该交易记录
- **Then**: 系统自动将持仓状态标记为 archived，持仓移入归档列表
- **Verification**: `programmatic`

### AC-5: 归档列表展示
- **Given**: 存在已归档的持仓数据
- **When**: 用户进入理财模块并切换到归档视图
- **Then**: 归档列表显示已清仓持仓的摘要信息
- **Verification**: `human-judgment`

### AC-6: 买入扣减现金
- **Given**: 用户添加一条买入交易记录且所属账户有现金账户
- **When**: 交易保存成功
- **Then**: 现金账户余额减少买入金额（含手续费）
- **Verification**: `programmatic`

### AC-7: 卖出增加现金
- **Given**: 用户添加一条卖出交易记录且所属账户有现金账户
- **When**: 交易保存成功
- **Then**: 现金账户余额增加卖出金额（扣手续费）
- **Verification**: `programmatic`

### AC-8: 自动创建现金账户
- **Given**: 用户添加交易记录且所属账户无现金账户
- **When**: 交易保存成功
- **Then**: 系统自动创建一个现金账户并完成资金流转
- **Verification**: `programmatic`

### AC-9: 交易记录关联现金账户
- **Given**: 用户查看持仓明细的交易记录
- **When**: 查看交易记录列表
- **Then**: 每条交易记录显示关联的现金账户名称
- **Verification**: `human-judgment`

### AC-10: 老数据兼容
- **Given**: 系统中存在历史持仓和交易数据
- **When**: 用户加载理财模块
- **Then**: 历史数据正常显示，无现金账户关联的交易不受影响
- **Verification**: `programmatic`

### AC-11: 清仓自动填充数量和价格
- **Given**: 用户在明细弹窗中添加交易记录
- **When**: 用户选择交易类型为"清仓"
- **Then**: 数量字段自动填充当前剩余持仓数量，价格字段自动填充当前价格
- **Verification**: `programmatic`

### AC-12: 列表数据与明细一致
- **Given**: 用户在明细中添加了买入或卖出交易
- **When**: 返回持仓列表
- **Then**: 持仓数量、成本价等字段根据交易明细自动更新
- **Verification**: `programmatic`

### AC-13: 金额自动计算
- **Given**: 用户在交易表单中填写了价格和数量
- **When**: 价格、数量、费用都填写完成
- **Then**: 金额字段自动计算并显示（价格 × 数量）
- **Verification**: `programmatic`

### AC-14: 归档盈亏计算正确
- **Given**: 某持仓已清仓归档
- **When**: 用户查看归档持仓的明细
- **Then**: 最终盈亏 = 卖出总金额 - 买入总金额 - 总费用，最终收益率 = 最终盈亏 / 买入总金额 × 100%
- **Verification**: `programmatic`
