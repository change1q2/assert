# 收支分析饼图 redesign - Product Requirement Document

## Overview
- **Summary**: 将收支分析页面（Records.jsx）中的收入占比和支出占比饼图，从当前的实心SVG饼图改为带外部标签的空心环形饼图，并增加「一级分类 / 全部」切换按钮，支持在大类视图和明细视图之间切换。
- **Purpose**: 提供更清晰直观的收支结构可视化，支持不同粒度的数据查看，提升用户对收支构成的理解效率。
- **Target Users**: 所有使用收支分析功能的用户

## Goals
- 收入占比和支出占比改用空心环形饼图样式
- 饼图每个扇区外侧显示标签（名称 + 百分比）
- 收入占比支持「一级分类 / 全部」切换
- 支出占比支持「一级分类 / 全部」切换
- 一级分类视图：展示大类（如餐饮、交通、工资、理财等）
- 全部视图：展示所有二级分类明细
- 使用 Recharts 组件库实现，保持与项目技术栈一致

## Non-Goals (Out of Scope)
- 不修改数据统计逻辑（仅修改展示层）
- 不修改其他页面的饼图（Overview、Analysis 等页面不在本次范围）
- 不增加饼图交互（点击钻取等不在本次范围）
- 不修改账本筛选、时间筛选等已有功能

## Background & Context
- 当前 Records.jsx 中收入占比和支出占比使用原生 SVG 绘制的实心饼图，下方有网格状图例
- 数据结构：`income` / `expense` 数组，每个元素包含 `category`、`amount`、`percent`
- 类别数据来自 `categories` state，结构为 `{ income: { '大类': ['二级分类1', ...] }, expense: { ... } }`
- 项目已使用 Recharts 图表库（Analysis、AssetClasses 等页面均有使用）
- 参考设计图：空心环形饼图，扇区外侧有引导线和标签（名称+百分比）

## Functional Requirements

### FR-1: 空心环形饼图
- 收入占比和支出占比均改为空心环形饼图（innerRadius + outerRadius）
- 使用 Recharts PieChart / Pie 组件实现
- 饼图颜色与现有配色体系保持一致

### FR-2: 扇区外部标签
- 每个饼图扇区在外侧显示标签
- 标签内容：分类名称 + 百分比（保留1位小数）
- 标签与扇区之间有引导线（labelLine）
- 标签位置避免重叠，由 Recharts 自动布局

### FR-3: 一级分类 / 全部 切换
- 收入占比卡片标题右侧增加「一级分类」「全部」切换按钮组
- 支出占比卡片标题右侧增加「一级分类」「全部」切换按钮组
- 按钮组样式：圆角胶囊形，选中态为蓝色填充白色文字，未选中为灰色背景深色文字
- 两个饼图的切换状态相互独立

### FR-4: 一级分类视图数据
- **收入占比一级分类**：按收入大类聚合（工资、理财、其他收入等）
- **支出占比一级分类**：按支出大类聚合（餐饮、交通、居住、购物、医疗、教育、娱乐、投资、其他支出等）
- 聚合规则：同一大类下所有二级分类的金额相加
- 百分比基于大类金额占总收入/总支出的比例计算

### FR-5: 全部视图数据
- **收入占比全部**：展示所有二级分类明细（如工资、奖金、补贴、利息、分红等）
- **支出占比全部**：展示所有二级分类明细（如早餐、午餐、晚餐、公交、地铁等）
- 百分比基于二级分类金额占总收入/总支出的比例计算

## Non-Functional Requirements

- **NFR-1**: 切换时数据实时更新，无明显延迟
- **NFR-2**: 饼图在不同屏幕尺寸下自适应大小
- **NFR-3**: 标签文字颜色符合深色/浅色模式适配

## Constraints

- **Technical**: React + Recharts 组件库，Tailwind CSS 样式
- **Business**: 保持现有数据计算逻辑不变，仅改变展示维度
- **Dependencies**: 依赖已有的 categories 状态数据和 records 数据

## Assumptions

- 一级分类的定义与 `categories` state 中的第一层 key 对应
- 全部视图中的数据按 category + subCategory 两级聚合
- 百分比保留1位小数
- 颜色分配按大类维度保持一致（同一大类在两种视图下颜色相同）

## Acceptance Criteria

### AC-1: 空心环形饼图显示
- **Given**: 用户打开收支分析页面
- **When**: 页面加载完成且有收支数据
- **Then**: 收入占比和支出占比均显示为空心环形饼图
- **Verification**: `human-judgment`

### AC-2: 扇区外侧标签显示
- **Given**: 饼图有数据
- **When**: 查看饼图
- **Then**: 每个扇区外侧有标签显示分类名称和百分比（1位小数）
- **Verification**: `human-judgment`

### AC-3: 一级分类 / 全部 切换按钮
- **Given**: 饼图卡片已渲染
- **When**: 查看卡片标题区域
- **Then**: 标题右侧有「一级分类」和「全部」两个按钮，当前选中态高亮
- **Verification**: `human-judgment`

### AC-4: 一级分类视图数据正确
- **Given**: 点击「一级分类」按钮
- **When**: 饼图更新
- **Then**: 饼图扇区数量等于大类数量，各扇区值为该大类下所有二级分类金额之和
- **Verification**: `programmatic`

### AC-5: 全部视图数据正确
- **Given**: 点击「全部」按钮
- **When**: 饼图更新
- **Then**: 饼图扇区数量等于所有二级分类明细数量，各扇区值为对应二级分类的金额
- **Verification**: `programmatic`

### AC-6: 切换交互流畅
- **Given**: 当前显示一级分类视图
- **When**: 点击「全部」
- **Then**: 饼图平滑切换到全部视图，标签同步更新
- **Verification**: `human-judgment`

### AC-7: 收入和支出切换独立
- **Given**: 收入占比切换到「全部」
- **When**: 查看支出占比
- **Then**: 支出占比的视图状态不受影响，保持各自独立
- **Verification**: `programmatic`

### AC-8: 空数据处理
- **Given**: 某一时间范围内无收入/支出数据
- **When**: 查看对应饼图
- **Then**: 显示「暂无数据」占位提示
- **Verification**: `human-judgment`

## Open Questions
- 一级分类视图下，同一大类的颜色在全部视图中是否需要保持一致？
- 全部视图中标签数量较多时，是否需要做显示上限处理？
