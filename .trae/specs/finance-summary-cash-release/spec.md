# 持仓汇总行修复 + 现金余额联动 + 释放资金 - 需求规格

## 概览
- **摘要**: 修复持仓/归档表格合计行缺失列数据、统一账户详情现金类资产统计口径、为交易记录增加「释放资金」字段、卖出交易自动联动现金余额资产
- **目的**: 提升财务数据的展示完整性与自动化，让用户在查看持仓汇总、进行交易时能看到完整的资金流转信息
- **目标用户**: 个人资产管理系统用户，使用理财模块进行投资跟踪和交易记录管理

## 目标
1. 归档持仓的合计行显示「最终盈亏」数值和「最终收益率」
2. 账户详情页中所有现金类资产（按 assetType / categoryL1 双重匹配）都计入「现有余额」
3. 交易记录中卖出类型（卖出/清仓）显示「释放资金」= 卖出金额 - 税费
4. 卖出交易时释放的资金自动累加到对应账户本的「现金余额」资产中；若不存在则提醒用户创建

## 非目标
- 不修改后端数据模型（仅前端逻辑调整）
- 不改变交易记录的存储结构（释放资金为计算字段，不持久化）
- 不影响买入/建仓交易的现有流程
- 不修改独立资产模块的相关逻辑

## 背景与上下文

### 问题 1: 归档持仓合计行缺失「最终盈亏」
- 文件: `FinanceHoldingsTable.jsx` L1480-L1592
- 归档表格列定义在 `FinanceHoldingsTable.utils.js` L131-L145，包含 `finalPnl`（最终盈亏）和 `finalPnlPercent`（最终收益率）
- 合计行（tfoot）仅处理以下列 key: `cost`, `currentValue`, `holdingPnl`, `holdingPnlRate`, `dailyPnl`, `dailyPnlRate`
- `finalPnl` 和 `finalPnlPercent` 没有专门处理逻辑，落入默认分支（L1589）渲染空 `<td>`

### 问题 2: 账户详情页「现有余额」统计口径不一致
- 文件: `Accounts.jsx`
- `balanceData` (L1025-L1052) 按 `assetType/assetKind === '现金' || '货币基金'` 筛选
- `holdingsSummary` (L1748-L1768) 按 `categoryL1 === '现金类'` 筛选
- 详情页展示 (L2072) 优先使用 `holdingsSummary`，但可能漏掉 `assetType='现金余额'` 但 `categoryL1` 未标记为「现金类」的资产
- 现有逻辑需要将两种筛选方式统一

### 问题 3: 交易记录缺少「释放资金」字段
- 文件: `Finance.jsx` 交易记录展示 (L2106-L2250)
- 交易记录当前展示 4 列: 价格/净值、数量/份额、金额、费用
- 卖出/清仓交易缺少「释放资金」展示
- 释放资金 = 卖出总金额 - 交易税费 = |amount| - fee

### 问题 4: 卖出交易未自动联动现金余额资产
- 文件: `Finance.jsx`
- `updateCashAccount` (L1122-L1150): 更新现金账户余额，但仅查找已存在账户
- `saveTradeRecords` (L576-L702): 保存交易记录并更新 financeAssets
- 当前卖出流程: 更新账户余额 → 更新 cash 类型 financeAsset 的 currentValue
- 缺失: 
  1. 没有向用户确认/提醒是否存在「现金余额」类型资产
  2. 没有将释放资金直接加到现金余额资产的 shares/quantity 上
  3. 缺少「无现金余额资产」的用户提示

## 功能需求

### FR-1: 归档持仓合计行显示最终盈亏
归档持仓表格底部合计行需要计算并展示所有分页归档持仓的「最终盈亏」合计值和「最终收益率」。

### FR-2: 统一现金类资产统计口径
账户详情页「现有余额」卡片的计算逻辑需要同时匹配以下条件的资产:
- `categoryL1 === '现金类'`（一级分类为现金类）
- `assetType === '现金'` 或 `assetType === '现金余额'` 或 `assetType === '货币基金'`
- `assetKind === '现金'` 或 `assetKind === '货币基金'`

### FR-3: 交易记录显示释放资金
在交易记录列表中，对卖出类型（卖出/清仓/快速过户）的交易记录增加「释放资金」展示字段。

### FR-4: 释放资金自动累加到现金余额资产
当用户创建卖出/清仓交易记录时:
1. 系统自动查找对应账户下是否存在「现金类 > 现金余额」类型的资产
2. 若存在: 自动将释放资金（= 卖出金额 - 税费）加到该资产的 shares/quantity 中
3. 若不存在: 弹出提示告知用户需要先创建「现金余额」类型资产才能完成卖出资金释放

## 非功能需求

### NFR-1: 数据一致性
修改后的逻辑需确保账户余额、现金类资产 shares、交易记录三者保持一致，不可出现数据不同步。

### NFR-2: 向后兼容
已存在的归档持仓数据、现金类资产数据、交易记录需不受影响。

### NFR-3: 响应性能
释放资金的自动累加计算应为同步操作，不可引入额外异步延迟。

## 约束

### 技术约束
- 前端框架: React + Vite
- UI 库: Tailwind CSS
- 状态管理: React Context + useState
- 数据持久化: 通过 fetchState/saveState API 与后端交互

### 业务约束
- 释放资金为计算字段（= 卖出金额 - 税费），不需要单独持久化到数据库
- 货币类型不一致时（交易货币 vs 账户货币）需跳过自动累加

### 依赖
- `convertCurrency` 函数用于跨币种金额换算
- `updateAccountBalance` 和 `updateCashAccount` 现有函数

## 假设
1. 用户已在系统中配置了至少一个账户
2. 现金余额资产类型为 `assetType: '现金余额'` 且 `categoryL1: '现金类'`
3. 快速过户交易类型不触发释放资金联动（仅卖出/清仓）
4. 货币基金类型的资产不参与释放资金逻辑（货币基金本身就是现金类资产的特殊形式）

## 验收标准

### AC-1: 归档持仓合计行显示最终盈亏
- **类型**: `rule`
- **给定**: 归档持仓 tab 下存在若干条归档持仓记录
- **当**: 切换到归档持仓 tab 并查看表格底部合计行
- **则**: 合计行的「最终盈亏」列显示该页所有记录的 finalPnl 折算合计值，「最终收益率」列显示加权平均收益率
- **通过条件**: 合计行 finalPnl 列值非空且数值正确；finalPnlPercent 列值非空
- **证据**: `FinanceHoldingsTable.jsx` 合计行 tfoot 中存在 `col.key === 'finalPnl'` 和 `col.key === 'finalPnlPercent'` 的处理分支

### AC-2: 账户详情页现有余额正确统计现金类资产
- **类型**: `rule`
- **给定**: 账户详情页下存在 `categoryL1='现金类'` 和 `assetType='现金余额'` 的资产
- **当**: 查看「现有余额」卡片
- **则**: 所有符合现金类条件的资产都被计入余额统计
- **通过条件**: 现有余额数值等于所有现金类资产 currentValue 按 CNY 折算之和
- **证据**: `Accounts.jsx` holdingsSummary 的筛选条件覆盖 categoryL1 + assetType + assetKind

### AC-3: 交易记录显示释放资金字段
- **类型**: `rule`
- **给定**: 交易记录列表中存在卖出/清仓类型的记录
- **当**: 查看该条交易记录
- **则**: 显示「释放资金」字段，数值 = |amount| - fee
- **通过条件**: 卖出/清仓记录均显示释放资金；买入/建仓/分红不显示
- **证据**: `Finance.jsx` 交易记录渲染中存在释放资金列

### AC-4: 卖出交易自动联动现金余额资产
- **类型**: `rule`
- **给定**: 用户在资产详情页创建一条卖出交易记录
- **当**: 该记录保存成功
- **则**: 对应账户下的「现金余额」类型资产 shares 自动增加释放资金金额
- **通过条件**: 保存后现金余额资产的 shares/quantity 字段值增加释放金额
- **证据**: `handleAddRecord` → `saveTradeRecords` 流程中存在自动累加逻辑

### AC-5: 无现金余额资产时提醒用户
- **类型**: `rule`
- **给定**: 用户创建卖出交易记录，但该账户下不存在「现金余额」类型资产
- **当**: 尝试保存卖出交易
- **则**: 弹出提示对话框，告知用户需要先创建现金余额资产
- **通过条件**: 用户看到明确的提示信息；不影响交易记录的正常保存（仅跳过自动累加）
- **证据**: `handleAddRecord` 中存在检查 cashAsset 是否存在的分支

### AC-6: 构建验证通过
- **类型**: `rule`
- **覆盖**: 全部 AC
- **通过条件**: `npm run build` exit code 0
- **证据**: 构建日志

### AC-7: 视觉一致性与交互流畅度
- **类型**: `rubric`
- **规模**: 1-5
- **锚点**: 1=样式混乱/交互断裂；3=基本可用，风格大致匹配；5=完美匹配现有模块风格
- **通过阈值**: >= 4
- **证据**: 组件样式与现有 Finance 模块保持一致
