# 理财模块 - 归档持仓显示优化与交易本金联动 PRD

## Overview
- **Summary**: 优化理财模块归档持仓列表的显示字段，移除不适用于归档数据的实时行情字段（当前市值、持仓盈亏、持仓盈亏率、当日盈亏、当日收益率、仓位占比），增加最终盈亏和最终收益率字段；调整筛选条件与列表字段一致（只保留列表中出现的筛选项）；优化筛选汇总显示最终总盈亏和最终总收益率（最终总收益率=最终总盈亏/理财模块总成本×100%）；实现交易记录本金与所属账户余额的联动扣减/增减。
- **Purpose**: 当前归档持仓列表显示了不适用于历史已清仓数据的实时行情指标，导致用户困惑；同时筛选条件与列表字段不一致；筛选汇总口径不符；交易本金未与账户余额联动，无法反映真实资金流动。
- **Target Users**: 个人资产管理系统的理财模块用户，需要清晰查看历史持仓盈亏和交易资金流转的投资者。

## Goals
- 优化归档持仓列表字段，移除实时行情指标，增加最终盈亏和最终收益率
- 调整归档持仓的筛选条件，只显示列表中存在的字段对应的筛选项
- 优化筛选汇总显示最终总盈亏和最终总收益率（以理财模块总成本为分母）
- 实现交易记录本金与所属账户余额的联动

## Non-Goals (Out of Scope)
- 不会修改活跃持仓列表的显示逻辑
- 不会修改交易记录的创建和保存流程
- 不会修改清仓归档的核心流程
- 不会实现部分清仓功能

## Background & Context
- **现有架构**: 前端 React (Finance.jsx) + 后端 Node.js + MySQL
- **归档数据**: 存储在 `financeAssetArchives` 表中，包含最终盈亏和最终收益率字段
- **账户体系**: 账户存储在 `accounts` 表中，每个账户有 id、name、balance、currency 等字段
- **交易联动**: 当前交易记录已实现与现金账户的联动，但所属账户（非现金账户）的余额未联动

## Functional Requirements

### FR-1: 归档持仓列表字段优化
- 归档持仓列表中移除以下字段：当前市值、持仓盈亏、持仓盈亏率、当日盈亏、当日收益率、仓位占比
- 归档持仓列表中增加以下字段：
  - **最终盈亏**: 从归档数据的 `finalPnl` 字段读取，该值由交易明细统计得出（finalPnl = 卖出总金额 − 买入总金额 − 所有费用）
  - **最终收益率**: 从归档数据的 `finalPnlPercent` 字段读取（finalPnlPercent = finalPnl / 买入总金额 × 100%）
- 归档持仓列表保留的字段：市场、货币、资产种类、资产名称、代码、持仓成本、平均买入成本、数量、天数、清仓日期、最终盈亏、最终收益率、所属账户、操作

### FR-2: 归档筛选条件调整
- 归档持仓的筛选条件只显示列表中存在的字段对应的筛选项
- 归档列表字段为：市场、货币、资产种类、资产名称、代码、持仓成本、平均买入成本、数量、天数、清仓日期、最终盈亏、最终收益率、所属账户
- 因此归档筛选条件仅保留：全部账户、全部市场、全部货币、全部资产种类（与列表字段一一对应，移除一级/二级/三级/四级分类、持仓分组、持仓分类等筛选项）
- 筛选条件切换逻辑需根据当前视图（活跃/归档）动态调整

### FR-3: 筛选汇总优化
- 筛选汇总区域只显示以下指标：
  - **最终总盈亏**: 筛选结果中所有归档持仓的 finalPnl 之和（按汇率统一换算为 CNY）
  - **最终总收益率**: 最终总盈亏 / 理财模块的总成本 × 100%
- "理财模块的总成本"定义：`financeAssets` 中所有未归档持仓的 `cost`（= costPrice × shares，按汇率换算为 CNY）之和
- 移除原有的当前总市值、持仓总成本、持仓总盈亏、持仓总收益率、当日总盈亏、当日总收益率等指标
- 汇总指标根据筛选条件动态计算

### FR-4: 交易本金与账户余额联动
- 用户新增交易记录时，交易本金自动与对应所属账户的余额联动：
  - 买入/建仓交易：从所属账户（accountId 所指账户，非"现金账户"）的 `balance` 中扣减交易本金（含手续费）
  - 卖出/清仓交易：向所属账户的 `balance` 中增加交易本金（扣除手续费）
  - 分红交易：不影响账户余额（仅记录分红金额到现金账户）
- 交易记录保存时自动同步更新所属账户的 `balance` 字段
- 账户余额更新需考虑货币单位一致性（账户币种与交易币种不一致时不更新，保留现金账户逻辑）
- 保留原有的"现金账户"联动逻辑（买卖金额最终体现在现金账户上）

## Non-Functional Requirements

### NFR-1: 数据一致性
- 交易处理必须是原子操作：更新持仓、更新账户余额、保存交易记录必须在同一事务中完成
- 任何一步失败则全部回滚

### NFR-2: 性能
- 归档列表加载时间不超过 2 秒
- 交易保存操作响应时间不超过 1 秒

### NFR-3: 向后兼容
- 老归档数据（无 finalPnl/finalPnlPercent）必须正常显示，缺失值显示为 0
- 已有的账户余额数据不受影响

## Constraints
- **技术**: React + JavaScript（前端）、Node.js + Express（后端）
- **框架**: 前端使用 Ant Design + Tailwind CSS
- **数据**: 归档数据需确保 finalPnl 和 finalPnlPercent 字段存在
- 已实现的现金账户联动不可回退，需在此基础上叠加所属账户余额联动

## Assumptions
- 用户已在账户管理中配置了至少一个账户
- 归档持仓的最终盈亏和最终收益率已在清仓时正确计算
- 账户余额字段用于记录可用资金，交易本金直接操作该字段
- 所属账户余额与现金账户余额为两个独立的资金池，均需正确维护

## Acceptance Criteria

### AC-1: 归档列表字段显示正确
- **Given**: 存在已归档的持仓数据
- **When**: 用户切换到归档持仓视图
- **Then**: 列表显示资产名称、代码、清仓日期、最终盈亏、最终收益率等字段，不显示当前市值、持仓盈亏、持仓盈亏率、当日盈亏、当日收益率、仓位占比字段
- **Verification**: `programmatic`

### AC-2: 归档筛选条件正确
- **Given**: 用户在归档持仓视图
- **When**: 查看筛选条件
- **Then**: 筛选条件只包含与归档列表字段对应的筛选项（市场、货币、资产种类、所属账户），不包含一级/二级/三级分类、持仓分组、持仓分类等筛选项
- **Verification**: `programmatic`

### AC-3: 筛选汇总显示正确
- **Given**: 存在已归档的持仓数据和活跃持仓数据
- **When**: 用户切换到归档持仓视图
- **Then**: 汇总区域只显示最终总盈亏和最终总收益率；最终总收益率 = 最终总盈亏 / 理财模块所有持仓的总成本 × 100%
- **Verification**: `programmatic`

### AC-4: 交易本金扣减所属账户余额
- **Given**: 用户添加一条买入/建仓交易记录且所属账户有足够余额
- **When**: 交易保存成功
- **Then**: 所属账户（accountId 对应账户）余额正确扣减（交易本金 + 手续费）
- **Verification**: `programmatic`

### AC-5: 交易本金增加所属账户余额
- **Given**: 用户添加一条卖出/清仓交易记录
- **When**: 交易保存成功
- **Then**: 所属账户（accountId 对应账户）余额正确增加（交易本金 − 手续费）
- **Verification**: `programmatic`

### AC-6: 老数据兼容
- **Given**: 系统中存在历史归档数据
- **When**: 用户加载理财模块
- **Then**: 历史归档数据正常显示，无最终盈亏的显示为 0
- **Verification**: `programmatic`

### AC-7: 货币单位一致性校验
- **Given**: 交易币种与所属账户币种不一致
- **When**: 用户保存交易
- **Then**: 所属账户余额不进行联动更新（仅保留现金账户逻辑，现金账户币种与交易币种一致）
- **Verification**: `programmatic`

## Open Questions
- [x] 交易本金是否需要检查账户余额是否充足？→ 本期不检查，允许透支
- [x] 归档持仓是否支持再次编辑？→ 不支持，仅作只读历史记录
- [x] "理财模块的总成本"分母取值 → 取 `financeAssets` 所有未归档持仓的 cost 之和（跨币种按汇率换算为 CNY）
